# @questerix/core

> Shared Type Bridge — Single Source of Truth for Supabase Database Types

This package is the **canonical home** for all Supabase-generated TypeScript types shared across the Questerix platform. Both the Admin Panel (React) and the Student App (Flutter — via a manual Dart adaptation layer) draw their schema knowledge from here.

---

## Why this exists

Without a shared type package, schema changes require simultaneous manual updates in every consumer:

- `admin-panel/src/lib/database.types.ts` (React)
- `questerix-student-app/lib/data/models/` (Flutter; path may vary in the student-app repo)

With `@questerix/core`, there is one command to run after every Supabase migration, and TypeScript consumers automatically get the latest types via an import alias.

---

## Regenerating Types After a Schema Change

After applying any Supabase migration (`supabase db push`), run:

```bash
# From workspace root
npm run typegen

# Or from packages/core/
npm run typegen
```

This runs:

```
supabase gen types typescript --project-id bkfhorslctqieetzqdtd > src/types/database.types.ts
```

## React (Admin Panel) — How to Consume

The Admin Panel imports via the `@questerix/core` alias, configured in `vite.config.ts` and `tsconfig.json`:

```typescript
// New canonical import (preferred for new code)
import type { Database, Tables } from "@questerix/core";

// Legacy import still works (via re-export shim in admin-panel/src/lib/database.types.ts)
import type { Database } from "@/lib/database.types";
```

## Flutter (Student App) — Consumption Path

Flutter/Dart cannot directly consume TypeScript types. The bridging strategy is:

### Option A — Manual Dart Mirror (Current)

The Flutter app maintains hand-written Dart models in `questerix-student-app/lib/` (e.g. `lib/data/models/`). After a schema change:

1. **Review** the diff in `packages/core/src/types/database.types.ts`
2. **Update** the corresponding Dart model in `student-app/lib/data/models/`
3. **Run** `dart analyze` to catch type errors in the Flutter codebase

### Option B — Generated Dart (Future)

Consider [`supabase-codegen`](https://pub.dev/packages/supabase_codegen) or a custom script that reads the TypeScript types and generates Dart equivalents. This would make the Flutter side fully automated.

**Pattern for schema drift detection:**

```dart
// In your Drift schema (questerix-student-app/lib/.../database.dart),
// use the same column names as the Supabase schema.
// Then the TypeScript types act as the contract specification.
```

## Directory Structure

```
packages/core/
├── package.json          — Package manifest (@questerix/core)
├── README.md             — This file
└── src/
    ├── index.ts          — Barrel exports (Database, Tables, Json, Enums)
    └── types/
        └── database.types.ts  — AUTO-GENERATED by Supabase CLI (do not edit manually)
```

---

## Rules

- ❌ **Never edit `database.types.ts` by hand.** Always regenerate via `npm run typegen`.
- ❌ **Never add business logic to this package.** Types only.
- ✅ Always regenerate after `supabase db push` or any migration.
- ✅ Commit the regenerated types alongside the migration in the same commit.
